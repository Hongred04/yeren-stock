# 智能股票监控系统 · 野人体系

把「全能的野人」交易体系完整落地的量化选股 + 买卖点建议系统。

## 一键启动

```bash
python 启动系统.py            # 启动看板（自动开浏览器）
python 启动系统.py --report   # 只跑命令行自检报告
python 启动系统.py --port 8899
```

看板地址：<http://127.0.0.1:8777>

## 打开速度

| 场景 | 耗时 | 说明 |
|---|---|---|
| **再次打开页面** | **0.01-0.03s** | 命中结果缓存，秒开 |
| 完整重扫（K线已缓存） | ~30s | 全市场快照 10s + 情绪池历史 |
| 完整重扫（K线冷启动） | 40-80s | 首次需拉取K线 |

**打开即用**：前端先尝试读结果缓存（8秒超时保护），命中直接渲染；
未命中才启动后台任务，并**实时显示进度条 + 当前阶段 + 已耗时**（如"拉取K线 136/197… 62s"）。

三层加速：
1. **结果缓存**（3分钟 TTL）— 重复打开秒回
2. **K线内存缓存**（进程内，二级）— 二次读取 0.02s
3. **K线磁盘预载**（批量 listdir 替代 N 次 stat）— 22.9s → 0.27s，提速 85 倍

## 看板导航（一级 → 二级菜单）

所有结论按主题拆成 5 个一级板块，每个板块下挂二级页面，**一次只看一页**，
不再是把十几块内容堆在一屏里找。当前页面记在 localStorage，刷新后还停在原来那一页。

| 一级 | 二级页面 | 看什么 |
|---|---|---|
| **今日总览** | 今日结论 · 仓位计划 | 一句话结论 + 三问速览；该拿多少仓位 + 5 步推演 |
| **市场情绪** | 情绪温度计 · 题材主线 · 涨停梯队 | 0-100 温度 + 连板梯队；五信号判题材持续性；涨停池明细 |
| **资金动向** | 主力资金流 · 龙虎榜席位 | 涨停股题材资金流 / 板块资金流；机构·北向·游资席位 |
| **选股决策** | 候选股票 | 打分清单 → 点开个股看买卖点、止损、K线、详情 |
| **我的持仓** | 持仓体检 · 自选观察 | 复用卖出信号给持仓体检；自选股只盯不做 |

一级菜单自带角标：市场情绪显示当前**温度**、选股决策显示**候选股数量**、
我的持仓显示**体检告警条数**；二级菜单上「题材主线」在主线成立/一日游时打红点。
点涨停池、持仓、自选里的股票会自动跳到「选股决策」并展开详情（仅当天候选股有详情）。

## 四套预设策略（随时切换）

| 预设 | 适用 | 关键差异 |
|---|---|---|
| **野人原版** | 缩量题材短线 | 股价5-10元、市值<100亿、权重 35/30/35 |
| **激进打板** | 情绪高位接力 | 放宽至30元/300亿，权重 25/20/55（想象力主导） |
| **保守波段** | 周期票 | 必须均线多头排列，权重 45/30/25 |
| **超短首板** | 极度聚焦 | 排除科创/北交/创业，只做主板低价 |

在看板右侧「策略配置」面板可逐项调参（阈值、权重、开关），保存后立即重新选股。

## 扩展模块（E1-E3，参考 GitHub 同类项目新增）

野人原体系（M1-M10）之外，参考 GitHub 上几个 A 股开源项目补了三个「钱和情绪」的
观测模块，**不改变原体系的判定口径**，只作为独立面板与 M8 体检的补充证据。

| 模块 | 作用 | 灵感来源 |
|---|---|---|
| **E1 情绪温度计** | 连板梯队 / 炸板率 / 封板率 / 晋级率 / 赚钱效应 / 涨跌家数 → **0-100 温度** + 冰点→启动→发酵→高潮→退潮六阶段定位 + 温度曲线 | 连板系列「情绪周期」、slingshot 市场宽度、limit-up-dao 封板质量 |
| **E2 龙虎榜·游资席位** | 每日龙虎榜上榜股（净买入榜）+ 营业部席位聚合，自动识别 **机构专用 / 北向 / 知名游资**（拉萨天团、溧阳路、桑田路、绍兴帮…） | a-stock-data 龙虎榜席位层、slingshot、aiagents-stock 游资跟踪 |
| **E3 主力资金流** | ① 涨停股按题材聚合的主力净流入（今天涨停的钱砸在哪个方向）②候选股主力净额/净占比 ③行业板块资金流排行（best-effort） | a-stock-data 资金面层、slingshot 沪深港通 |

**E1 温度算法**：涨停家数(30) + 连板高度(25) + 炸板率(20) + 晋级率/涨跌宽度(25)；
温度从高位骤降 ≥18° 或亏钱面积 ≥30% 时给出**退潮预警**。M3 判「能不能出手」，
温度计看「今天多少度」，两者互补。

**E2 与 M10 的联动**：候选股若当日登龙虎榜，详情页会打上席位标签（如「龙虎榜·机构专用」
「龙虎榜·绍兴帮」）——机构专用偏向机构票（离场=加速减仓），知名游资偏向游资票
（离场=断板节奏）。席位绰号为公开复盘常用口径、非官方认定，仅供识别资金性质参考。

> 数据降级：板块资金流（东财 clist）在部分网络下会限流，此时面板自动隐藏该表，
> 只展示更可靠的「涨停股题材资金流」与候选股资金流；龙虎榜盘中未披露时回退到最近一期。

## 我的持仓 · 自选（本地记录 + 体检）

把「我今天该干什么」落到实处：在页面「我的持仓 ▸ 持仓体检 / 自选观察」录入你买了的股票
（成本 / 股数），或用选股详情页的「＋记持仓 / ＋加自选」一键录入。

加/删之后会在底部弹一个提示（如「已加入自选 · 某某（共 3 只）」），点提示里的
**「去看看」**直接跳到对应页面；详情页按钮是状态感知的——已在自选就显示
「✓ 已在自选（点此移除）」，再点一次即移出。一级菜单「我的持仓」上的角标：
有告警显示告警条数（红），没告警显示正在跟踪的自选数。

每次扫描用**同一套卖出信号**给每只持仓做体检——盈亏 + 该不该走：

- 复用 S1 退潮清仓 / S3 破位止损 / S4 A字杀 / S6 机构加速 / S7 断板 / S8 庄股回避；
- 归为「清仓离场 / 减仓 / 观察·减半 / 持有」四档，红色告警并入 M8 纪律体检；
- 数据落本地 `data/portfolio.json`，纯本地、不上行，`/api/portfolio` 可增删改查。

## 买卖点体系

**买入**
- B1 首板试错 — 新周期首板，回踩不破介入
- B2 龙头回踩 — 连板龙头回踩5日线，缩量企稳
- B3 缩量红盘低吸 — 极致缩量仍红盘，控盘好
- B4 尾盘博弈 — 节假日尾盘两点入场

**卖出**
- S1 退潮清仓 — 无条件清仓（最高优先级）
- S2 龙头止盈 — 五板以上分批止盈
- S3 破位止损 — 跌破10日线离场
- S4 A字杀警报 — 单日大跌立即走，绝不反包
- S5 去弱留强 — 弱于龙头则换仓
- S6 机构加速/破5日线 — 机构票专用（见 M10）
- S7 断板节奏 — 游资票专用（见 M10）
- S8 庄股回避 — 庄股不参与（见 M10）

## 主导资金分类（M10）

按主导资金给趋势分类，**离场点完全不同**；速度本身就是分类依据——
同样是五个板，游资一周走完（吃情绪溢价），机构一个月走完（吃波段收益）。

| 类型 | 量化特征 | 离场口径 |
|---|---|---|
| **机构票（中军）** | 流通 ≥80亿、近20日涨停 ≤1 次、单日最大波动 ≤7.5%、20日涨幅 5~60%、多站5日线 | 小阳线爬五日线、进二退一，波段持有 2~4 周；**离场信号 = 加速**——慢牛突然拉涨停（哪怕一个）= 出货冲顶，立刻减仓；破5日线先减半 |
| **游资票（龙头）** | 近10日涨停 ≥2 次或当前 ≥2 连板 | 连板/断板节奏，两板一断、两板一断；离场跟着断板节奏走——断板日盯回封，**断板2天不回封 = 节奏破坏，撤** |
| **庄股** | 低波动阴跌/横盘（日均 ≤2.8%、无涨停）后近10日出现 ≤-7% 断崖大阴 | **不参与**。做庄失败打回原点，盈亏比极差；持仓遇断崖无条件出 |

系统对每只候选股自动分类（选股表徽标 + 详情页「主导资金」面板），
买入建议按类型拦截（庄股直接「不参与」），卖出建议按类型追加 S6/S7/S8。

## 题材主线五信号（M9）

一条题材主线行情的成立，需要 5 个信号**按时间顺序依次共振，缺一环就是「一日游」**：

| # | 信号 | 系统怎么判 | 缺环后果 |
|---|---|---|---|
| S1 | **消息定级别** | 默认**自动定级**：抓取 7x24 快讯（新浪财经直播→同花顺→东财快讯降级），关键词规则分级（国家战略S→部委政策A→行业事件B→个股公告C），只统计与主题材相关的快讯；面板手动录入优先 | C 级或消息不够大 → 直接按一日游，后面都不用看 |
| S2 | **首日看合力** | 涨停池按题材聚类：题材内同日涨停 ≥3 家且开盘 60 分钟内封板 ≥2 家，板块指数带量创 60 日新高 | 无合力 = 资金没集体行动，孤军奋战就是一日游 |
| S3 | **中军定容量** | 题材板块成分股里流通 ≥100 亿的大票是否异动（涨幅 ≥3%） | 无中军 = 游资脉冲，当天冲高就结束 |
| S4 | **老龙是前兆** | 本地「老龙档案」（历史 ≥3 连板个股）今日是否有异动（≥5%） | 引信未点燃 → 降级观察 |
| S5 | **次日定生死** | 昨日涨停池 → 今日开盘：空间龙候选平均高开 ≥3%、首板活口留存 ≥50%、中军最弱不破 -2% | 次日检验不过 = 主线地位不成立 |

四种结论：**主线成立 / 首日启动·待次日验证 / 信号不全·仅观察 / 一日游特征·回避接力**，
结论联动 M8 纪律体检（一日游 → 黄色提醒「题材内不接力」）。

**数据口径与冷启动**：题材以涨停池行业板块为代理；板块指数/成分股走东财行业板块接口，
取不到时降级为「未验证」不硬性否决；昨日涨停池与老龙档案由本地
`data/pool_history/` 逐日归档积累（每天第一次扫描自动存档），刚启用前几天 S4/S5 显示
「积累中/待验证」属正常。

## 关键风控设计

退潮判定需**同时满足**「亏钱面积 ≥ 阈值」+「至少一条结构信号」，避免单日节前效应被误判为周期退潮。退潮/极度缩量时，名单标记为「观察储备」，不给出买入建议。

### 快照字段补全（参考 easyquotation）

腾讯 `qt.gtimg.cn` 的每行有 88 个字段，本系统原先只解析到第 48 个。参考
[easyquotation](https://github.com/shidenggui/easyquotation) 的字段表补齐了后面
一直在返回、却没被用上的 5 个：

| 字段 | 索引 | 用途 |
|---|---|---|
| **量比** | 49 | 当日放量程度。≥2.0 计入「显著放量」理由，<0.8 计入「量能偏冷」警示（不参与打分，避免动选股口径） |
| 委差 | 50 | 买卖盘力度差 |
| **日内均价** | 51 | VWAP。详情页显示，并与现价比较着色（站上=红 / 跌破=绿） |
| 市盈(动) | 52 | 动态估值 |
| 市盈(静) | 53 | 静态估值 |

候选表「换手」列下方同时显示量比，扫一眼就能看出哪只放量、哪只缩量。
ETF 等品种字段数不足 54，取不到时返回 `None`、前端整块隐藏（**不会当成 0 参与计算**）。

## API

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/result` | GET | 取结果（优先缓存，秒回） |
| `/api/start` | GET | 启动后台分析，**立即返回** |
| `/api/status` | GET | 轮询进度 `{pct, progress, elapsed, running, done}` |
| `/api/invalidate` | POST | 使结果缓存失效 |
| `/api/config` | GET/POST | 读取/保存策略配置 |
| `/api/preset` | POST | 切换策略预设 |
| `/api/portfolio` | GET | 持仓/自选体检（按需拉快照与K线，不触发全市场重扫） |
| `/api/portfolio` | POST | 增改持仓 / 加删自选（`{action, code, name, cost, shares, date}`） |

> ⚠️ **两者返回结构不同，前端必须兼容**：`GET` 直接返回 view
> （`{holdings, watchlist, checks, n_holdings, n_watch, raw, ...}`），
> 而 `POST` 返回 `{ok: true, portfolio: view}` 包了一层。
> 前端统一走 `unwrapPort()` 取值，报告里的 `portfolio.raw` 是原始记录
> （代码/成本/股数，无行情），`holdings/watchlist` 才是体检后的结果。

| `/api/sources` | GET | 数据源状态：Cookie 配置 + 被熔断的接口 |
| `/api/sources` | POST | `{action}`：`save_cookie` / `unblock` / `auto` |

## 数据源治理（Cookie + 接口熔断）

点顶栏的 **「数据源」** 标签可以打开面板：粘贴东财 Cookie、查看被熔断的接口、手动解封。

### 关于「注入 Cookie 解决限流」——实测结论：对本问题无效

网上流传的做法是「东财限流 → 注入 Cookie 解决」。**实测（2026-10-08）证明这在
push2 接口上不成立**：

| 观察 | 结果 |
|---|---|
| 东财入口页（`www` / `quote` / `gridlist`）的 `Set-Cookie` | **完全没有** → 匿名设备 Cookie 无从获取 |
| `push2/api/qt/clist/get` | 请求发出后**服务端直接 RST**（`server closed abruptly`） |
| 同一域名、同一时刻 `ulist.np/get`、`ulist/get`、`stock/get` | **全部 200** |
| 带上 Cookie 再打被拦接口 | **一样失败** |
| `datacenter-web`（龙虎榜）、`push2ex`（涨停池）、腾讯行情 | 全部 200 |

结论：拦截发生在**连接层、按 URL 路径触发**（同一台机器同一时刻，不同 path 结果
完全不同），请求头里带什么都不会被读到。所以「带 Cookie 就能解限」不成立。

**本系统实际采用的方案**（才是真正有效的）：

1. **主口径走没被拦的接口** —— 资金流以 `ulist.np` 为主，被拦的 `clist` 只做补充；
2. **接口级熔断**（`_push2_json`）—— 确认被掐后冷却期内直接返回空、走降级链路，
   不再每轮扫描都在 3 台镜像上各撞一次超时。冷却随连续失败轮数指数退避
   （5 → 10 → 20 → 30 分钟封顶）；硬失败（RST）立即熔断，软失败（超时）连续 2 轮才熔断。
   健康接口不受影响（各自独立记账）。
3. **降级可见** —— 熔断中的接口会在顶栏「数据源」标签上显示，不再让人猜
   「板块资金流怎么没了」。

### Cookie 能力仍然保留

虽然对本问题无效，但 Cookie 注入是完整可用的（东财部分 `datacenter` 报表对已登录
会话的频控阈值更宽，将来若东财改成校验 Cookie 也能立刻接上）：

| 配置方式 | 说明 |
|---|---|
| 环境变量 `EAST_MONEY_COOKIE` | **优先级最高**，Windows `setx EAST_MONEY_COOKIE "..."` |
| 文件 `data/eastmoney_cookie.txt` | 面板里粘贴保存，或直接编辑；**按 mtime 热加载，改完即生效不用重启** |
| 面板「自动获取」 | 走 CookieJar 尝试收 `Set-Cookie`；实测拿不到，会如实提示 |

单行 `a=b; c=d` 和从 DevTools 复制来的多行格式都支持（会自动规范成分号分隔）。
Cookie **只注入东财域名**，腾讯等其它源不受影响。

> `data/eastmoney_cookie.txt` 已加入 `.gitignore` —— 凭证不进版本库。
