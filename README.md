# 智能股票监控系统 · 野人体系

把「野人体系」那套打法拆成能跑的规则：扫一遍全市场，给出候选股、买卖点和仓位建议。
纯本地运行，数据取自公开行情接口。

## 一键启动

```bash
python launcher.py            # 启动看板（自动开浏览器）
python launcher.py --report   # 只跑命令行自检报告
python launcher.py --port 8899
```

Windows 上直接双击 `start.bat` 也行（内部就是调 `launcher.py`）。

> 入口脚本叫 `launcher.py` 而不是中文名，是为了让 `.bat` 能安全引用，
> 含中文的批处理文件在不同代码页下容易乱码。

看板地址：<http://127.0.0.1:8777>

## 打开速度

| 场景 | 耗时 | 说明 |
|---|---|---|
| **再次打开页面** | 0.01-0.03s | 命中结果缓存，秒开 |
| 完整重扫（K线已缓存） | ~30s | 全市场快照 10s + 情绪池历史 |
| 完整重扫（K线冷启动） | 40-80s | 首次需拉取K线 |

前端先读结果缓存（8 秒超时保护），命中就直接渲染；
未命中才启动后台任务，并实时显示进度条 + 当前阶段 + 已耗时（如"拉取K线 136/197… 62s"）。

三层加速：
1. 结果缓存（3分钟 TTL）— 重复打开秒回
2. K线内存缓存（进程内，二级）— 二次读取 0.02s
3. K线磁盘预载（批量 listdir 替代 N 次 stat）— 22.9s → 0.27s，提速 85 倍

## 看板导航（一级 → 二级菜单）

所有结论按主题拆成 5 个一级板块，每个板块下挂二级页面，一次只看一页，
不再是把十几块内容堆在一屏里找。当前页面记在 localStorage，刷新后还停在原来那一页。

| 一级 | 二级页面 | 看什么 |
|---|---|---|
| **今日总览** | 今日结论 · 仓位计划 | 一句话结论 + 三问速览 + 明日判断；该拿多少仓位 + 5 步推演 |
| **市场情绪** | 情绪温度计 · 题材主线 · 涨停梯队 | 0-100 温度 + 连板梯队；五信号判题材持续性 + 板块强弱（主线/支线/最强板块）；涨停池明细 |
| **资金动向** | 资金在干什么 | 游资/机构/北向动向 + 主力主攻/撤离方向（席位明细不上界面，只出结论） |
| **选股决策** | 候选股票 · 信号胜率 | 打分清单 → 点开个股看买卖点、止损、适合什么策略、筹码分布、K线；信号胜率：历史信号 1/3/5 日复盘闭环 |
| **我的持仓** | 持仓体检 · 自选观察 | 复用卖出信号给持仓体检；自选股只盯不做 |

一级菜单自带角标：市场情绪显示当前温度、选股决策显示候选股数量、
我的持仓显示体检告警条数；二级菜单上「题材主线」在主线成立/一日游时打红点。
点涨停池、持仓、自选里的股票会自动跳到「选股决策」并展开详情。

### 任意股票都能点开看详情

任何一只股票都能点开看详情，不只限当天候选股，自选、持仓、涨停梯队里点
一只不在候选名单里的票，前端会按代码向后端要一份 `/api/stock?code=xxx`
（现拉该股快照 + 70 根K线），用和候选股完全相同的口径重新打分：
三要素分数、买卖点、主导资金分类、量比/均价、K线图全都有。

额外还会告诉你它为什么没进今天的候选（逐条复现 `screen()` 里的过滤条件），例如：

> 贵州茅台 · 综合评分 43.6 · 这不是今天的候选股
> 今天进不了候选，被这些硬条件挡下：换手 0.12% 低于下限 1.0%；未形成均线多头排列（策略要求必须多头）

代码格式自动兼容：手输自选/持仓时不用记着加前缀，填 `603466`、`000001`、
`300750` 这类 6 位裸数字，或券商常见的 `603466.SH` / `SH603466` 写法，系统都会
按交易所号段自动补成 `sh603466` / `sz000001` / `sz300750`（沪 600/601/603/605/688、
深 000/001/002/003/300/301、北 430/83x/87x/920）。已经存在 `portfolio.json` 里的
历史裸代码在读取时会自动规范化，不用手动删了重加。

结果按代码缓存，反复点同一只不会重复请求；取不到行情时给明确提示
（如「没取到 sz999999 的行情（代码可能不存在或已退市）」），不会点开一片空白。

## 策略：单套「野人体系」（自适应）

先说清口径：缩量不是买入条件，是市场状态。野人的体系平常以中长线波段为主、
不打板、不做短线；只有在市场缩量、资金撬不动大票时，才切到短线题材的应对打法。

原来的四套预设（野人原版 / 激进打板 / 保守波段 / 超短首板）已融合成这一套自适应体系：
选股口径相同，个股适合哪种打法由 `engine.style_fit` 判定，只写在股票详情页：

| 打法 | 判定 | 怎么打 |
|---|---|---|
| **中长线波段（平常打法）** | 机构主导 / 中军体量（≥150亿） / 均线多头+低涨停频率 | 沿5日线持有，小阳线爬坡不动手；突然加速拉涨停=派发，减仓 |
| **短线题材（缩量期应对打法）** | 小市值 / 连板基因 / 游资主导 | 小仓位、快进快出，只做首板与回踩企稳；节奏破坏就撤 |
| **庄股·不参与** | 断崖前面低波动、后单日大阴 | 不做（做庄失败打回原点，盈亏比极差） |

参数全部收进「调策略 → 高级参数（M1–M10 / E1–E3）」折叠菜单，那是系统骨架，
平常不用动，面板顶层只留策略说明。老存档里残留的旧预设（aggressive 等）会自动迁移。

## 扩展模块（E1-E4）

野人原体系（M1-M10）之外，又照着几个 A 股开源项目补了 E1-E4 四个「钱和情绪」的
观测模块。它们不改变原体系的判定口径，只作为独立面板与 M8 体检的补充证据。

| 模块 | 作用 | 参考 |
|---|---|---|
| **E1 情绪温度计** | 连板梯队 / 炸板率 / 封板率 / 晋级率 / 赚钱效应 / 涨跌家数 → 0-100 温度 + 冰点→启动→发酵→高潮→退潮六阶段定位 + 温度曲线 | 连板系列「情绪周期」、slingshot 市场宽度、limit-up-dao 封板质量 |
| **E2 龙虎榜·席位（内部）** | 每日龙虎榜 + 营业部席位聚合，识别 机构专用 / 北向 / 知名游资（拉萨天团、溧阳路、桑田路、绍兴帮…）——数据不上界面，只进「资金在干什么」结论 | a-stock-data 龙虎榜席位层、slingshot、aiagents-stock 游资跟踪 |
| **E3 主力资金流** | ① 涨停股按题材聚合的主力净流入（今天涨停的钱砸在哪个方向）②候选股主力净额/净占比 ③板块资金流排行（东财 ulist.np，行业+概念；受限时新浪兜底） | a-stock-data 资金面层、slingshot 沪深港通 |
| **E4 信号复盘档案** | 每次扫描记录可执行的买入信号，回验 1/3/5 日表现，按信号类型累计 样本数/胜率/平均收益；「选股决策 ▸ 信号胜率」页展示（含最近信号与结算状态） | quantitative_analysis 的因子/信号回验闭环 |
| **E5 低位承接方向** | 退潮期 + 存量博弈 + 机构专用席位净卖出 **三个闸门同时成立**才输出：推演「机构在高位兑现的那笔钱去哪」。按板块给「资金体量分位 / 资金强度分位 / 价格没抬起来的程度 / 首日净流入 / 有催化 / 板块角色」评分，取前 N 个方向，每个都带**操作口径（不追高）**与**仓位口径（退潮期试错仓）** | 用户 10-13 的一次真实复盘：10-12 退潮日判断「明日白酒老登股有一波小波段」，次日白酒Ⅱ 涨停 2 家、酿酒概念主力由负转正。这条判断的每一步都能用已有数据复现，原体系只是缺一个模块把它串起来 |

E1 温度算法：涨停家数(30) + 连板高度(25) + 炸板率(20) + 晋级率/涨跌宽度(25)；
温度从高位骤降 ≥18° 或亏钱面积 ≥30% 时给出退潮预警。M3 判「能不能出手」，
温度计看「今天多少度」，两者互补。

### 资金在干什么（席位数据只进这里）

龙虎榜/机构/北向的原始明细按用户要求下线，改为一句结论 + 逐项判断：

- 游资：知名席位净买/净卖多少、在接哪些票 → 「接力活跃」还是「在兑现」；
- 机构：机构专用席位净买/净卖 → 吸筹 or 高位派发；
- 北向：净买/净卖方向（盘中未披露时标注为最近一期）；
- 主攻/撤离方向：涨停股资金聚合 + 板块主力净流入排行；
- 一句话定调：如「游资接力、机构兑现，有热度、有派发，做题材不做高位大票」。

### 板块强弱（主线 + 支线 + 最强板块）

「题材主线」页在五信号之外新增板块强弱表：主线（涨停合力第一）+ 支线
（≥2 家涨停的第二梯队，含"资金支线"轮动预备队：有涨幅和资金、还没打出涨停合力），
强弱按 涨停家数/早封 | 板块涨幅 | 主力净额 三样合看，并直接给出
**当前最强板块**结论（明日看它的梯队加固还是断层）。

**板块资金记忆**：板块资金快照逐日归档（`data/board_flow_history.json`，留 40 天），
上榜板块标注「连续 N 日净流入」——单日流入没意义，连续方向才有
（资金连续堆几天的方向，远比今天冲进来一天的可信）。

**近 N 日板块轮动**：同一页下方一张表，逐日列出领涨板块（前 5，带涨跌幅），
并标出**最新一日相对前一日新进的方向** —— 看的是"资金从哪挪到哪"。
判读口径写在表下：领涨方向**连续**出现才算主线，一日游只算扰动。
数据来自财联社（`core/cls.py` 的 `sector_rotation`，近 4 日）；抓不到时整块隐藏，
不编造方向。手机端「市场情绪」页也有一张「板块轮动」卡（近 3 日）。

### 明日判断

挂在「今日结论」页：一句定调（防守/均衡/试攻）+ 五维判断（情绪/量能/题材/资金/
最强板块）+ 开盘先盯什么（带阈值：量能、亏钱面积、题材梯队）+ 若…则…情景预案。
它是推演不是预测，开盘后按实际读数修正。

### 信号胜率复盘（E4，胜率闭环）

每次扫描自动把可执行的买入信号记进档案（`data/signal_journal.json`），
之后回验每个信号的 1/3/5 日表现，累计出 样本数 / 胜率 / 平均收益，
回答「B1 首板、B2 回踩这些信号到底准不准」。页面：「选股决策 ▸ 信号胜率」。

**踩坑雷达**：同一页顶部，对每类信号看最近 8 笔**已结算**样本（`settled` +
`partial`，即 1 日收益已可算的），亏损 ≥5 笔就标红提醒 ——
「这不是信号烂，是你**用它的方式**在亏钱」，先停用、复盘、规避。
（买不到/停牌记 `skip` 的样本不参与统计。）

**回测正确性清单**（逐条落实，来自同类项目的踩坑结论）：

| # | 约束 | 落实方式 |
|---|---|---|
| 1 | t+1 成交（防未来函数） | 信号是收盘后给的 → 一律按次日开盘价进场 |
| 2 | 涨停不可买 | 次日开盘贴涨停（一字/秒板）→ 记「未成交」，不计入胜率 |
| 3 | 停牌过滤 | 次日无K线（停牌/退市）→ 记「未成交」 |
| 4 | 成本计入 | 佣金万2.5×2 + 印花税 0.05%（卖出）+ 滑点 0.05%×2 ≈ 0.2%，直接从收益扣除 |
| 5 | 逐档结算 | ret1/ret3/ret5 能算多少先落多少，ret5 出来才算最终结算 |
| 6 | 口径如实 | 不复权价、收盘结算、短线窗口近似，页面注明；超窗口档案过期归档 |

样本类说明：新信号的 3/5 日结果要等几天才出来，「跟踪中/已结算/未成交」都在页面上分开显示。

### 筹码分布量化

`core/chips.py`：没有 L2 就用经典近似，把每天的成交量按当日价格区间
（三角形分布）铺开、越久远权重越衰减，估算出：

- 获利盘 / 套牢盘比例（现价上下的筹码占比）
- 平均成本 + 成本乖离（现价 vs 平均成本）
- 筹码集中度（(p95−p5)/(p95+p5)）与 90% 成本区间
- 分布直方图（详情页：红=获利筹码 / 灰=套牢筹码，虚线=现价）

以前只能写文字的「筹码结构好 / 散户套牢躺平」现在是数字：获利盘 ≤25% 与
高集中度做小幅加分、获利盘 ≥92% 给警示（小权重，不动选股主口径）。
不复权口径，除权日附近有偏差（页面注明）。

> 数据降级（受限时指名道姓）：东财 push2 被限速时，板块数据自动退到新浪口径
> （只有涨幅/成交额/领涨股，无主力净额）并在面板与结论里标注「东财受限」；
> 两项都不可用时直接写明，不再含糊地说「接口异常」。龙虎榜盘中未披露时回退到最近一期。

## 我的持仓 · 自选（本地记录 + 体检）

把「我今天该干什么」落到实处：在页面「我的持仓 ▸ 持仓体检 / 自选观察」录入你买了的股票
（成本 / 股数），或用选股详情页的「＋记持仓 / ＋加自选」一键录入。

### 加自选：输名称就能搜（代码方式保留）

「管理」面板里的自选输入框**既收名称关键词，也收代码**——记不住代码时直接搜名字即可。

| 输入 | 识别结果 | 行为 |
|---|---|---|
| `茅台`、`银行` | 名称关键词 | 逐字搜索（防抖 220ms），下拉列出候选 |
| `gzmt` | 拼音首字母 | 同上（仅在线源支持拼音） |
| `600519`、`sh600519`、`600519.SH` | 代码 | **不发搜索请求**，点「加自选」直接加入 |

**匹配规则**（两个数据源合并，缺一不可）：

1. **本地名单**（`data/name_index.json`，全市场 6000+ 只）——**名称子串匹配**，召回完整。
   首次使用会用 `data/board_members.json` 冷启动（剔除「(已切换)」的作废旧代码），
   之后每次全市场扫描顺手用行情源的名字刷新（加 ST 前缀、更名都能跟上）。
2. **腾讯 smartbox 联想接口**——唯一支持**拼音首字母**，且名称比冷启动的板块表新。

为什么不能只用在线源：它是**联想**接口，结果条数有限（约 10 条）且**前缀优先**，
搜「银行」会被「银行ETF…」占满、真正的招商银行一个都出不来；也不覆盖全部北交所
（实测「贝特瑞」直接返回无结果）。本地名单正好补上这块。

合并后统一排序：**名称前缀 > 名称包含 > 拼音前缀 > 拼音包含**；同级**短名优先**、
再按代码升序（顺序稳定可复现，不会两次不一样导致点错）。只保留 A 股
（`sh/sz/bj`，含科创板 `GP-A-KCB`），港股/美股/ETF/基金/权证一律剔除。

**结果展示**：输入框下方实时下拉，每行显示 `名称 · 代码 · 板块`，命中的关键词高亮；
最多 8 条。点任意一行**立即加入自选**（名称一并写入）；已在自选的行置灰并标「已在自选」，
点了不会重复添加。名称唯一命中时点「加自选」直接加入；多条命中则列出候选让用户点选。

**空 / 无法匹配 / 接口异常**：

| 情况 | 表现 |
|---|---|
| 输入为空 | 不发任何请求、下拉收起；点「加自选」提示要输名称关键词或代码 |
| 搜不到 | 下拉里明说「未匹配到股票 —— 试试更短的关键词（如「茅台」「银行」），或直接输 6 位代码」，不静默失败 |
| 在线接口异常 | 自动改用本地名单兜底；提示「搜索接口这次没响应 —— 拼音搜索暂不可用，名称/代码不受影响」 |
| 在线异常且本地也无匹配 | 明确报错并引导「也可以直接输 6 位代码（如 600519）」 |

手机端「＋ 加自选」的底部表单同样支持（输名称/拼音搜，或直接输代码）。

加/删之后会在底部弹一个提示（如「已加入自选 · 某某（共 3 只）」），点提示里的
**「去看看」**直接跳到对应页面；详情页按钮是状态感知的——已在自选就显示
「✓ 已在自选（点此移除）」，再点一次即移出。一级菜单「我的持仓」上的角标：
有告警显示告警条数（红），没告警显示正在跟踪的自选数。

每次扫描用同一套卖出信号给每只持仓做体检——盈亏 + 该不该走：

- 复用 S1 退潮清仓 / S3 破位止损 / S4 A字杀 / S6 机构加速 / S7 断板 / S8 庄股回避；
- 归为「清仓离场 / 减仓 / 观察·减半 / 持有」四档，红色告警并入 M8 纪律体检；
- 数据落本地 `data/portfolio.json`，纯本地、不上行，`/api/portfolio` 可增删改查。

## 买卖点体系

> 两套口径，别混（对应野哥的「双账户」：大账户做波段、小账户做短线感受水温）：
> W 系列 = 波段（平常打法）、B/S 系列 = 短线（缩量期的应对打法）。
> 详情页按 `style_fit` 把匹配的那一路排在前面；禁买提示永远排最后。

**波段买入（M11）**
- W1 波段第一入场点 — 5日线上穿所有均线 + 20日线拐头向上，回踩 10/20 日线（要有爆量痕迹）
- W2 波段第二入场点 — 从 5 日线打到 20 日线附近（强庄）；或回踩 20 日线伴随缩量（弱庄）
- W3 波段第二波接入 — 第一波涨≥30%后回调、5日线重新拐头向上 + 均线高度粘合 → 等放量大阳突破后的回调介入（不追突破当天）

**波段卖出（M11）**
- WS1 波段离场点 — 高位放量大涨滞涨 = 有人在出货，先把利润装进口袋；
  若之后跌不下去（货出完股价不跌）= 有人接得住，反而是第二入场点

> 洗盘识别：缩量回踩 = 洗盘（不走）；放量破位 = 逻辑坏了（走）。
> 量价铁律：看周线和月线（日线可骗，周月线温和的量才是真相）。
> 波段短则 3 个月、长则半年，买的是信仰、逻辑、题材；锁仓（看懂主力意图）才可重仓。

**短线买入**（进场一律给具体价格与触发条件：分两笔怎么进、什么情况放弃）
- B1 首板试错 — 新周期首板：竞价高开 0~3% 先买一半，高开>5% 不追、等回踩补另一半，低开破位直接放弃
- B2 龙头回踩 — 连板龙头回踩 5 日线，缩量企稳分批接；止损=10日线/前低双保险
- B3 缩量红盘低吸 — 极致缩量仍红盘：回落 1% 附近分两笔，止损 -5%
- B4 尾盘博弈 — 节假日尾盘两点入场（仅节前最后交易日的尾盘窗口出现）

> 止损价 = 结构位与最大亏损双约束（取更高者），保证单笔试错亏损有上限（默认 ≤7%）。

**短线卖出**
- S1 退潮清仓 — 无条件清仓（最高优先级）
- S2 龙头止盈 — 五板以上分批止盈
- S3 破位止损 — 跌破10日线离场
- S4 A字杀警报 — 单日大跌立即走，绝不反包
- S5 去弱留强 — 弱于龙头则换仓
- S6 机构加速/破5日线 — 机构票专用（见 M10）
- S7 断板节奏 — 游资票专用（见 M10）
- S8 庄股回避 — 庄股不参与（见 M10）

## 主导资金分类（M10）

按主导资金给趋势分类，离场点完全不同；速度本身就是分类依据，
同样是五个板，游资一周走完（吃情绪溢价），机构一个月走完（吃波段收益）。

| 类型 | 量化特征 | 离场口径 |
|---|---|---|
| **机构票（中军）** | 流通 ≥80亿、近20日涨停 ≤1 次、单日最大波动 ≤7.5%、20日涨幅 5~60%、多站5日线 | 小阳线爬五日线、进二退一，波段持有 2~4 周；离场信号 = 加速——慢牛突然拉涨停（哪怕一个）= 出货冲顶，立刻减仓；破5日线先减半 |
| **游资票（龙头）** | 近10日涨停 ≥2 次或当前 ≥2 连板 | 连板/断板节奏，两板一断、两板一断；离场跟着断板节奏走——断板日盯回封，断板2天不回封 = 节奏破坏，撤 |
| **庄股** | 低波动阴跌/横盘（日均 ≤2.8%、无涨停）后近10日出现 ≤-7% 断崖大阴 | 不参与。做庄失败打回原点，盈亏比极差；持仓遇断崖无条件出 |

系统对每只候选股自动分类（选股表徽标 + 详情页「主导资金」面板），
买入建议按类型拦截（庄股直接「不参与」），卖出建议按类型追加 S6/S7/S8。

## 题材主线五信号（M9）

一条题材主线行情的成立，需要 5 个信号按时间顺序依次共振，缺一环就是「一日游」：

| # | 信号 | 系统怎么判 | 缺环后果 |
|---|---|---|---|
| S1 | 消息定级别 | 默认自动定级：多源快讯抓取（新浪7x24+滚动16页 / 央视新闻6页 / 同花顺 / 东财，池子上限2000条、回溯约一周），关键词规则分级（国家战略S→部委政策A→行业事件B→个股公告C）；消息记忆在有效期内兜底（S级20天/A级10天/B级5天）；面板手动录入优先 | C 级或消息不够大 → 直接按一日游，后面都不用看 |
| S2 | 首日看合力 | 涨停池按题材聚类：题材内同日涨停 ≥3 家且开盘 60 分钟内封板 ≥2 家，板块指数带量创 60 日新高 | 无合力 = 资金没集体行动，孤军奋战就是一日游 |
| S3 | 中军定容量 | 题材板块成分股里流通 ≥100 亿的大票是否异动（涨幅 ≥3%） | 无中军 = 游资脉冲，当天冲高就结束 |
| S4 | 老龙是前兆 | 本地「老龙档案」（历史 ≥3 连板个股）今日是否有异动（≥5%） | 引信未点燃 → 降级观察 |
| S5 | 次日定生死 | 昨日涨停池 → 今日开盘：空间龙候选平均高开 ≥3%、首板活口留存 ≥50%、中军最弱不破 -2% | 次日检验不过 = 主线地位不成立 |

四种结论：主线成立 / 首日启动·待次日验证 / 信号不全·仅观察 / 一日游特征·回避接力，
结论联动 M8 纪律体检（一日游 → 黄色提醒「题材内不接力」）。

**数据口径与冷启动**：题材以涨停池行业板块为代理；板块指数/成分股走东财行业板块接口，
取不到时降级为「未验证」不硬性否决；昨日涨停池与老龙档案由本地
`data/pool_history/` 逐日归档积累（每天第一次扫描自动存档），刚启用前几天 S4/S5 显示
「积累中/待验证」属正常。

**消息记忆（S1 的"前几天发的政策今天还认"）**：快讯池只能往前翻两三天
（新浪滚动约 50 条/页、央视约 80 条/页，再深就没有了），而大级别政策要管好几周。
所以每次定级出的 S/A/B 级结果会逐日归档到 `data/news_memory.json`，
有效期内（S 20天 / A 10天 / B 5天）持续参与 S1 判定，级别取「今日快讯 / 记忆」更高者；
证据里展示记忆原文与来源日期。实测案例：七部门印发《新型电池产业发展"十五五"规划》
发布三天后仍被记忆认定为 A 级（快讯池里早翻不到了）。C 级个股公告不记（噪声）。

**题材记忆（活跃榜）**：每日归档会记住当日活跃榜前 3（涨停≥2家），而不只是第一名，
题材连续几天在第 2、第 3 名爬坡（涨停家数、最高板逐日抬升）也算「已在启动中」，
不会等它登顶那天被当成「新题材首日」。页面还展示该题材的近期轨迹
（名次/涨停/最高板）与连续活跃天数（如「电池：09-30 第3名 → 10-08 第2名 →
10-09 第1名 · 连续 3 日活跃」）。实测教训：旧版只记第一名，电池启动第三天仍被报「首日」。

## 关键风控设计

退潮判定按野人原话口径：四种现象任一成立即退潮（亏钱面积 ≥30% / 中位股成排跌停 /
A字杀不反包 / 高度标的被闷杀）。盘中瞬时信号经 `stage_stabilizer` 滞回确认
（进入需连续 2 次跨 60s，退出需连续 2 次跨 180s 且面积回落），治「一会能出手一会退潮」。
退潮期不再一刀切：允许 0.5 成试错仓、只做首板（把 `ebb_trial_weight` 设 0 即回到
无条件清仓）；极度缩量优先于试错（量能不够连试错也停）。

### 快照字段补全（参考 easyquotation）

腾讯 `qt.gtimg.cn` 的每行有 88 个字段，本系统原先只解析到第 48 个。参考
[easyquotation](https://github.com/shidenggui/easyquotation) 的字段表补齐了后面
一直在返回、却没被用上的 5 个：

| 字段 | 索引 | 用途 |
|---|---|---|
| **量比** | 49 | 当日放量程度。≥2.0 计入「显著放量」理由，<0.8 计入「量能偏冷」警示（不参与打分，避免动选股口径） |
| 委差 | 50 | 买卖盘力度差 |
| **日内均价** | 51 | VWAP。详情页显示，并与现价比较着色（站上=红 / 跌破=绿） |
| 市盈(动) | 52 | 动态估值 |
| 市盈(静) | 53 | 静态估值 |

候选表「换手」列下方同时显示量比，扫一眼就能看出哪只放量、哪只缩量。
ETF 等品种字段数不足 54，取不到时返回 `None`、前端整块隐藏（不会当成 0 参与计算）。

### 通达信（TDX）源：为什么它一直是「不可用」

通达信走 **TCP 7709**，不按 IP 封，所以被当作日K线/指数K线的**首选源**。
但它长期显示不可用，原因有三层，都跟「库装没装」无关：

1. **选错了服务器**。mootdx 不指定 server 时会用 `~/.mootdx/config.json` 里的
   `BESTIP`，那份配置可能指向一台**早已下线**的机器（实测本机 BESTIP
   `218.6.170.47` 连不上）→ 每次 K 线调用白等 4~15 秒后返回空。更麻烦的是
   mootdx 的 `config.set()` **只改内存、不落盘**，所以每次启动都会重新读回那台
   死服务器 —— 通达信等于永远没用上。
2. **「TCP 连得上」≠「能出数据」**。实测 55 台候选里 14 台 TCP 通，
   **只有 1 台真能返回 K 线**（通达信服务端协议近年改过，大量老站点只应答
   「股票列表」这类请求，K线/行情一律回空）。
3. **复权路径与新版 pandas 不兼容**。mootdx 的复权实现用了
   `fillna(method='ffill')`，pandas 2.2+ 已移除该参数 → `adjust="qfq"` 必崩
   （Python 3.13 又没有 pandas<2.2 的 wheel，降级只能源码编译）。

对应的修法（v1.30.0）：

- **自己选服**：并行 TCP 探活 → 对活下来的逐个**真拉一次 K 线**，选出第一台
  能出数据的，显式传给 mootdx；结果落盘 `data/tdx_server.json` 复用，
  失败/断连自动重选。**只探一次**，不会每次开面板都白等。
- **占位 K 线清洗**：盘中（尤其开盘前）服务器会回一根
  `open==close==high==low` 且成交量为 `5.877471754111438e-39`
  （协议里「空」字段的位模式）的假 K 线。拿 `vol <= 0` 判会漏（那个数 > 0），
  按 `vol < 1` 判才能剔掉 —— 否则会凭空多出一根"一字板"，
  把 `_graph_score` / 洗盘判定全带偏。
- **复权兼容垫片**：只在复权调用期间给 `DataFrame.fillna` / `Series.fillna`
  补回 `method=` 参数，用完立刻还原（`data.factor` 是 Series，只补 DataFrame
  等于没补 —— 这个坑实测踩过）。复权失败自动退回不复权，不会整条链路失败。
- **覆盖范围**：日K线 + **指数日K**（`index_bars`）。指数日K是量能分位/环比的
  数据底座，多一层首选源就多一层保险。
- 数据源面板那一行会直接显示**选中的服务器**（如
  `可用（K线首选源）· 117.34.114.14:7709`），不再是笼统一句"不可用"。

> 装了才有：`pip install -r requirements.txt`（只有 `mootdx` 一个可选依赖）。
> 没装也能跑，只是自动退回腾讯/新浪。`start.bat` 会优先选用装了它的解释器，
> 并在启动时打印 `TDX source: available / not installed`。

## 数据源治理（所有源的实时状态 + 接口熔断）

点顶栏的 「数据源」 标签打开面板：**逐个列出系统用到的每一个数据源**及其实时状态。

| 字段 | 说明 |
|---|---|
| 状态 | `正常` / `降级` / `受限` / `不通` / `未启用` / `未使用` |
| 名称 · 厂商 · 主机 | 如「行情快照 · 腾讯 · qt.gtimg.cn」 |
| 说明 | `正常` → 最近成功时间 + 耗时；`降级` → 哪项关键数据没取到、用的几秒前的快照；`受限` → 冷却剩余、连续失败轮数；`不通` → 失败时间与原因；`未使用` → 本次运行还没轮到 |
| 用途 | 这个源供什么数据（如「主力净额 · 涨跌家数 · 板块清单」） |

按 **行情 / K线 / 资金 / 情绪池 / 消息** 五组排列，共 19 个源；有问题的排在同组最前。
顶栏标签同步显示「受限 · N 个异常」或「全部正常 · 19 个源」。

**状态怎么来的**：取自**最近一次真实使用**的记录，不另发探测请求 ——
`_get` 是全系统唯一的 HTTP 出口，在那里记一笔（谁、何时、成没成、花了多久），
再加上东财 push2 的熔断/预算、通达信的可用性、关键数据的降级标记。
面板里再打一轮探测既慢、又会消耗东财的每分钟额度（甚至把熔断撞出来），得不偿失。
所以「未使用」= 本次运行还没轮到它，而不是故障。

面板底部两个操作：**「清除熔断记录」**（立即重试被熔断的接口）与
**「重连」**（丢弃 keep-alive 连接池，挂机久了取不到行情时用）。

### 关于「注入 Cookie 解决限流」——实测结论：对本问题无效（已移除该配置）

网上流传的做法是「东财限流 → 注入 Cookie 解决」。实测（2026-10-08）证明这在
push2 接口上不成立：

| 观察 | 结果 |
|---|---|
| 东财入口页（`www` / `quote` / `gridlist`）的 `Set-Cookie` | 完全没有 → 匿名设备 Cookie 无从获取 |
| `push2/api/qt/clist/get` | 请求发出后服务端直接 RST（`server closed abruptly`） |
| 同一域名、同一时刻 `ulist.np/get`、`ulist/get`、`stock/get` | 全部 200 |
| 带上 Cookie 再打被拦接口 | 一样失败 |
| `datacenter-web`（龙虎榜）、`push2ex`（涨停池）、腾讯行情 | 全部 200 |

结论：拦截发生在连接层、按 URL 路径触发（同一台机器同一时刻，不同 path 结果
完全不同），请求头里带什么都不会被读到。所以「带 Cookie 就能解限」不成立。

**本系统实际采用的方案**（才是真正有效的）：

1. 主口径走没被拦的接口，资金流以 `ulist.np` 为主，被拦的 `clist` 只做补充；
2. 接口级熔断（`_push2_json`）—— 确认被掐后冷却期内直接返回空、走降级链路，
   不再每轮扫描都在 3 台镜像上各撞一次超时。冷却随连续失败轮数指数退避
   （5 → 10 → 20 → 30 分钟封顶）；硬失败（RST）立即熔断，软失败（超时）连续 2 轮才熔断。
   健康接口不受影响（各自独立记账）。
3. 降级可见，熔断中的接口会在顶栏「数据源」标签上显示，不再让人猜
   「板块资金流怎么没了」。

> **Cookie 配置已在 v1.29.0 整体移除**（前端入口、后端接口、数据层注入全删）。
> 既然实测证明它对限流无效，「留着当备用」只是让面板多一块没人用得上的配置项 ——
> 数据源面板现在只回答一个问题：**每个源现在通不通**。
> 遗留的 `data/eastmoney_cookie.txt`（如果本机还有）已无人读取，可以自行删除。

### 「取不到行情 / 找不到这只股票」怎么排查

长驻进程挂机久了，可能出现明明代码没错却提示取不到行情（自选股全部失去详情）。
按顺序排查：

1. 代码格式，最常见。裸 6 位数字（`603466`）或券商格式（`603466.SH`）现在都会
   自动补前缀；若仍失败，确认前缀与交易所匹配（沪 6 开头 / 深 0、3 开头 / 北 4、8、9 开头）。
2. 连接池残留（v1.11.2 已自愈）—— keep-alive 池里的连接被服务端关掉后，
   旧版本会把空包当合法响应静默返回，于是报「代码可能不存在或已退市」这种误导性错误。
   现已在 `_get` 里校验响应、发现坏包就丢弃重试。若仍怀疑，去「数据源」面板点
   **「重连」**（`POST /api/sources {action:"reconnect"}`）强制丢弃连接池。
3. 确实停牌/退市，错误信息会照实说明，不是 bug。

> 判别小技巧：换一个刚启动的进程试同样的代码。如果新进程能取到、老进程取不到，
> 就是连接池问题（第 2 条），不是代码问题。

### push2 限速：换镜像没用，得少打（v1.13.0）

实测（2026-10-09）把这件事查清楚了：

| 观察 | 结论 |
|---|---|
| `clist/get` 在 push2 / 1.push2 / 82.push2 三台全 RST | 不是单台故障 |
| 同一时刻 `push2his` 的板块K线、`push2ex` 涨停池、腾讯行情全部正常 | 不是网络问题 |
| 但 `ulist.np` 在连续打了几十次之后，也变成全 RST | 是"打得太多"触发的 |
| 一旦触发，`push2` / `1.push2` / `82.push2` / `push2his` / `push2delay` 一起歇菜 | 整个家族一起被限，多镜像≠多额度 |
| 冷却几分钟后自行恢复 | 是限流不是封禁 |

**所以真正的解法是"少打 + 别撞"，而不是"换个接口继续打"：**

1. 全局限速闸门：所有 push2 请求串行化，最小间隔 0.35s + 抖动；并发从 8 降到 2。
   之前 8 个 worker 并发轰正是触发主因。
2. 家族级冷却：一旦被 RST，所有 push2 调用一起退避 3 分钟起、指数延长到 15 分钟，
   不再让每个接口各自去撞一遍（那只会把冷却越撞越长）。
3. 能不查就不查：
   - 板块清单固化成 `core/board_seed.py` 随包发布 → 首启/换机 零请求
   - 板块资金流缓存 10 分钟（原来 3 分钟）
   - 板块成分表只扫前 1200 只、三天重建一次
4. 换独立来源兜底：东财被限速时，板块面板退到新浪口径
   （`newSinaHy.php` / `newFLJK.php`，另一台主机、另一套风控）。
   只有涨跌幅/成交额/领涨股、没有主力净额，界面会如实标注。

### 板块数据整体改走 ulist.np

`clist` 和 `ulist.np` 是同一个 push2 服务的不同路径、字段完全一样，
而 `ulist.np` 的额度明显更宽松。所以：

| 原来（clist） | 现在 |
|---|---|
| 板块资金流 `fs=m:90+t:2`（只有行业） | ulist.np 批量查 `90.BKxxxx`，行业+概念一起排，含领涨股 |
| 板块列表 `fs=m:90+t:2` | 枚举 `90.BK0001~BK1399` 自发现（17 请求扫出 731 个板块），落盘 + 随包种子 |
| 成分股 `fs=b:BKxxxx` | 用个股 `f100`(所属行业)/`f103`(所属概念) 自建成员表 |

顺带两个白赚的好处：概念板块也能排进资金流榜首（短线真正的主战场），
**概念板块也有成分股了**（原来 clist 只喂行业板块，M9 中军验证遇概念题材只能走弱验证）。

## 情绪阶段为什么不再来回跳（v1.13.0）

退潮判定原本基于瞬时的三分池计数：

```
亏钱面积 = (跌停 + 炸板) / (涨停 + 跌停 + 炸板) ≥ 0.30 → 退潮
```

盘中这三个数一直在跳：10:30 一波炸板把面积顶过阈值就报「退潮、无条件清仓」，
十分钟后新涨停补上来又变回「可出手」。这不是市场变了，是采样噪声。

现在过一遍 `core/stage_stabilizer.py`（施密特触发器）：

| 动作 | 条件 |
|---|---|
| 进入退潮 | 原始信号连续 2 次、跨 60s；但亏钱面积超阈值一个身位(0.15)可直接认 |
| 退出退潮 | 连续 2 次、跨 180s，且面积回落到阈值下方 0.10 才认（出门比进门难） |
| 开盘保护 | 开盘头 30 分钟样本太薄，只认强信号（否则每天 9:35 都先报一次退潮） |

状态分四档：`calm` / `watch`(退潮预警，未确认) / `ebb` / `recovering`。
实测一段 30 帧的噪声序列：原始信号跳变 20 次，稳定后只切换 0 次。
E1 温度计的口径也统一到同一份确认结果，两个页面不再各说各话。

## 退潮期可以 0.5 成试错（v1.13.0）

原来退潮一律 0 仓、禁止开仓。现在按野哥的规矩：退潮期允许 0.5 成试错仓，只做首板。

- 配置项 `M3_sentiment.ebb_trial_weight`（默认 `0.05` = 0.5 成），设为 0 就回到无条件清仓
- 只对首板给开仓建议；连板股一律不参与（退潮里接力就是接刀子）
- 仓位链显示「退潮试错」档，目标总仓位 0.5 成
- 极度缩量优先：量能不够时连试错也停

## 自动刷新（v1.13.0）

打开页面后每分钟静默刷新一次：拉 `/api/live`（只查当前候选/自选/持仓的行情，
并重算情绪阶段，实测 50~70ms，不触发全市场重扫），就地把行情与结论贴回界面。

- 不弹遮罩、不跳页、不打断正在看的详情、保持滚动位置
- 服务器上有更新的一份报告时静默换上
- 全市场重扫按 5 分钟在后台触发（一分钟扫一次纯属自己找限速）
- 切回前台立刻补一次；顶栏「自动」可一键关掉
- 顶栏右侧显示「刷新时间 · 稳定后的阶段」，例如 `10:30:00 · 退潮`

**「换新报告」靠什么触发**（v1.31.0 修过一处静默失效）：前端比对
`/api/live` 返回的 `result_ts` 与本地记录的版本号，不同才去取新报告。
所以 `/api/live` **必须始终给出 `result_ts`** —— 它原先只读内存结果缓存，
而那份缓存有 3 分钟 TTL，过期后 `result_ts` 与 `picks` 双双丢失，
`quotes` 也跟着空 → 页面打开后就**永久冻结在那一份报告上**，行情不再更新。
现在回退到磁盘那份（与 `/api/result` 同一口径），两者始终一致。

另外两条相关的兜底：

- **端出「上次结果」时会如实标注**（服务器标 `stale`，或报告日期不是今天）——
  顶栏日期显示 `20261013（上次结果·正在后台刷新）`，并自动补一次扫描；
  不做这一步，页面会一直把旧数据当今天的看。
- **渲染出错不拖垮自动刷新**：`finish()` 用 `finally` 保证 `startAuto()` 一定执行。
  否则 `render()` 抛一次异常（数据里少个字段就会），静默刷新就永远不启动。
